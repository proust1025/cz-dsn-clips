# 抖音切片自动抓取

每天自动搜索「陈泽 × 迪士尼在逃公主」连麦打 PK 的直播切片，下载点赞 > 1000 且没下过的新视频里点赞最高的前 3 个，无水印归档到 `~/Movies/抖音切片/`。浏览器后台最小化运行，不挡你工作。

## 三条命令

```bash
./run.sh login    # 首次使用 / 登录失效时：扫码登录抖音（这个窗口需要你扫，不会最小化）
./run.sh run      # 立刻跑一次抓取（每晚 20:00 自动跑的也是这个，窗口自动最小化到后台）
./run.sh check    # 检查登录态是否还有效
```

`run` 支持这些可选参数：

```bash
./run.sh run --dry-run          # 只采集不下片，用来看当前能抓到什么
./run.sh run --limit 10         # 本次最多下 10 个（不改配置，只对这一次生效）
./run.sh run --days 182         # 临时把时间范围放宽到半年（1/7/182/0）
./run.sh run --dry-run --days 182 --limit 20
```

三个参数可以任意组合，都只对本次生效，不会改 `config.json`。日常每晚 8 点跑的是配置里的默认值。

试运行会在 `~/Movies/抖音切片/_每日报告/` 生成 `日期-试运行.md`，不会和正式报告混淆。

## 目录结构

```
douyin-harvest/
├── config.json        配置文件，改关键词和点赞门槛都在这
├── harvest.py         主程序：搜索 → 过滤 → 去重 → 下载
├── login.py           一次性扫码登录
├── core.py            公共函数
├── run.sh             入口脚本
├── chrome-profile/    抖音登录态（别删，删了要重新扫码）
└── data/
    ├── seen.db        已下载清单，用来去重
    ├── cookies.txt    给 yt-dlp 用的 cookie
    └── logs/          每天的运行日志

~/Movies/抖音切片/
├── 2026-08-30/        按发布日期归档
├── 2026-08-31/
└── _每日报告/          每天的抓取清单
```

文件命名格式：`发布日期_作者_点赞数_标题.mp4`，例如
`2026-08-30_某某切片_3.2w赞_陈泽迪士尼连麦名场面.mp4`

## 改配置

编辑 `config.json`：

| 字段 | 说明 |
| --- | --- |
| `keywords` | 搜索关键词数组，想加词直接往里加 |
| `min_likes` | 点赞门槛，默认 1000（达不到的不下） |
| `max_download_per_run` | 每次最多下载几个，默认 3（按点赞从高到低取前 N 个） |
| `publish_time` | 时间范围：`1`=最近一天 `7`=最近一周 `182`=半年 `0`=不限 |
| `sort_type` | 排序：`0`=综合 `1`=最多点赞 `2`=最新发布 |
| `output_dir` | 保存位置 |
| `scroll_rounds` | 每个关键词滚动几次，调大能捞更多但更慢、更易触发风控 |
| `require_both_names` | 设为 `true` 则只保留标题同时含「陈泽」和「迪士尼」的视频，更精准但会漏 |
| `headless` | 后台无窗口模式。抖音对无头浏览器查得严，不建议开 |

**后台运行**：自动抓取时 Chrome 会被推到屏幕外并最小化（见 `core.launch_browser(minimize=True)` + `minimize_chrome_window`）。`login.py` 不传 minimize，因为你要扫码看二维码。

改完不用重启任何服务，下次运行自动生效。

## 出问题怎么办

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 提示登录态失效 | cookie 过期，一般几个月一次 | 跑 `./run.sh login` 重新扫码 |
| 提示疑似触发验证码 | 抖音风控 | 手动打开浏览器访问抖音，过一次滑块验证，再重跑 |
| 抓到 0 条 | 关键词太冷门或时间范围太窄 | 放宽 `publish_time`，或往 `keywords` 加词 |
| 下载失败 | 网络波动或视频已删除 | 程序会自动记进报告，下次运行重试 |
| 提示上次任务仍在运行 | 上次异常退出留下了锁 | 删掉 `data/.lock` 文件即可 |

排查时先看 `data/logs/` 里当天的日志。

## 飞书多维表格同步

每次 `run` 跑完后会自动把新下载的视频同步到飞书多维表格，无需手动操作。

- 表格：https://my.feishu.cn/base/YAdIbvvwraxTRDsPtDwcV51tnbe
- 字段：标题（主）、抓取时间、视频链接、转发量、发布日期、点赞量、评论数、视频附件
- 默认视图按「抓取时间」倒序排列（最新的在最上面）
- 同步脚本：`sync_feishu.py`（读 `seen.db` 里 `feishu_synced=0` 的记录，批量建行 + 上传视频附件，幂等）

**字段变更说明**：原「播放量」列已删除（抖音 web 端不提供播放量，接口恒返回 0，留空反而误导）；新增「抓取时间」列（来自 `seen.db` 的 `crawled_at`），用于按最新抓取排序。发布日期 / 点赞 / 评论 / 转发 / 链接 / 附件都正常填充。

如需单独补同步（例如重跑）：`python3 sync_feishu.py`（在 `douyin-harvest/` 目录下运行）。
